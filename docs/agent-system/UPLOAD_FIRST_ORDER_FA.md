# ترتیب بارگذاری و مرجع حقیقت

## ترتیب بارگذاری فایل‌ها

**اگر مخزن خالی است:** کل محتویات داخل `01_UPLOAD_TO_GITHUB/SORTING-OS/` را به ریشه مخزن `SORTING-OS` منتقل کن؛ خود پوشه‌ی wrapper یعنی `SORTING-OS` را به‌عنوان یک زیرپوشه اضافه نکن. این محتوا شامل کد پایه، مستندات، پرامپت‌ها، قراردادها و فایل‌های GitHub است.

**اگر مخزن از قبل محتوا دارد:** هیچ فایلی را ابتدا overwrite نکن. ابتدا Prompt 00 را در حالت فقط‌خواندنی/بدون تغییر اجرا کن، گزارش را بررسی کن، سپس یک شاخه جدید بساز و ادغام کنترل‌شده انجام بده.

## بعد از آپلود

1. در GitHub تأیید کن که `README.md`, `PROJECT_SPEC.md`, `docs/`, `desktop/`, `prompts/`, `contracts/`, `reference-inputs/` و `.github/` در ریشه هستند.
2. در Arena.ai همان repository و branch را باز کن؛ نام مشابه کافی نیست، owner و URL مخزن را بررسی کن.
3. پرامپت مادر `MASTER_PROMPT_FOR_AGENT_FA.md` را به‌عنوان دستورهای پایدار پروژه تنظیم کن، اگر Arena امکان project instructions دارد. اگر نه، آن را در آغاز نشست عامل وارد کن.
4. فقط Prompt 00 را اجرا کن و منتظر گزارش بمان.

## منبع حقیقت و تعارض‌ها

1. قوانین حفظ داده، صحت مالی و امنیتی این مخزن.
2. خواسته‌های صریح و جدید مالک پروژه، تا وقتی با صحت مالی/امنیت و داده‌های قبلی تعارض نداشته باشد.
3. `PROJECT_SPEC.md` و مشخصات پذیرفته‌شده در `docs/`.
4. تصمیم‌های تأییدشده در `docs/decision-log.md` و ADRها.
5. اسناد قدیمی در `reference-inputs/` که باید با مستندات جاری تطبیق داده شوند.
6. پیشنهادهای عامل؛ پیشنهاد عامل تا زمانی که ثبت و تأیید نشده، تصمیم قطعی نیست.

اگر دو منبع تعارض دارند، عامل باید تعارض را گزارش کند و **حق ندارد خودش بی‌صدا یکی را انتخاب کند**؛ به‌ویژه در کدینگ حساب‌ها، واحد مبلغ، نحوه تسویه، موجودی، مهاجرت داده یا Windows 7.

## نکته درباره اسناد مرجع

`reference-inputs/` برای نگهداری و تطبیق سندهای مبناست؛ به معنی اجرای بی‌چون‌وچرای تمام دستورهای قدیمی نیست. عامل باید تعارض‌ها و نسخه مرجع انتخابی را در `docs/decision-log.md` ثبت کند.
